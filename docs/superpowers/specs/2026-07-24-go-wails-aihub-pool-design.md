# AIHub Desktop Go 重写与号池设计

状态：设计草案

## 目标

将现有 Electron 桌面端重写为 Go 应用，移除 Electron 和 Node 运行时。核心业务、AIHub 接口、配置管理、号池和本地代理全部由 Go 实现；界面采用 Wails v2，允许保留 TypeScript/HTML/CSS 作为 WebView 界面层。

第一版重点是稳定的 AIHub 用户号池和本地 LLM 重试代理，而不是复刻管理员后台。

## 范围

### 保留的桌面功能

- AIHub 用户登录、2FA、刷新会话和退出
- 余额、用量、Token、调用趋势、公告、订阅、支付和兑换
- 用户 API Key 的查看、创建、启停、复制和删除
- Codex、Codex WebSocket、OpenCode 配置读取、切换、备份和回滚
- Windows 托盘、单实例、后台常驻和安装包

### 新增的本地代理

- 自动重试 429、502、503、504、529
- 固定间隔、指数退避和 Retry-After
- SSE 透明转发，仅在首字节前重试
- 使用当前登录用户的 AIHub Key 构建号池
- Key 冷却、轮换、恢复和失败原因统计
- 展示请求数、重试数、延迟、错误和当前分组
- 自动配置 Codex/OpenCode 使用本地代理
- 默认退出时恢复直连配置
- 可选后台常驻代理

### AIHub 号池

- 同步用户可用分组、倍率、平台、模型能力和 Key
- 手动同步和定时同步，默认间隔 5 分钟
- 同步失败继续使用最近一次成功快照
- 用户多选允许进入号池的分组
- 分组调度策略只保留“最低倍率优先”
- 同倍率分组使用稳定顺序
- 先在当前分组内轮换健康 Key，整个分组不可用后再切换下一倍率分组
- 分组恢复后新请求回到最低倍率分组
- 支持按选中分组清空全部远程 Key
- 删除前重新同步、二次确认、显示数量和进度，失败项可单独重试
- 可选为缺少 Key 的选中分组补齐 Key；不自动创建

## 非范围

- 任何管理员接口和管理员功能
- 多上游路由
- 竞速请求
- 首 Token 优先或倍率与速度混合调度
- 公网代理
- 提示词、响应正文和完整 Key 日志
- Linux/macOS 发布版

## 架构

```text
Wails 界面
    |
    v
Go 应用服务
    |- 用户认证与 DPAPI 安全存储
    |- AIHub 用户 API 客户端（固定白名单）
    |- 用户 Key/分组同步器
    |- 本地号池与健康状态
    |- HTTP/SSE 重试代理（127.0.0.1）
    |- Codex/OpenCode 配置服务
    |- 日志、统计、托盘和生命周期
    |
    v
AIHub 用户接口（/auth、/keys、/groups、/usage 等）
```

AIHub 用户 Key 是唯一凭据来源。本地号池只保存运行时视图、冷却状态和统计，不产生另一套本地 Key。

## 用户接口边界

Go 客户端只允许普通用户接口，例如 `/auth/*`、`/keys/*`、`/groups/*`、`/usage/*`、`/subscriptions/*`、`/payment/*` 和 `/announcements/*`。路径校验必须拒绝 `/admin` 及未登记路由，代码中不实现管理员 Token 或管理员数据模型。

## 代理行为

1. 请求进入本地代理后，根据端点和模型筛选兼容分组。
2. 按倍率从低到高选择分组。
3. 在当前分组选择健康 Key，注入其上游鉴权信息。
4. 对指定状态码执行重试；429 优先遵守 Retry-After。
5. 首字节前允许切换 Key 或分组；首字节后只透传，不重试。
6. Key 失败进入按错误类型区分的冷却状态；成功后清除连续失败级别。
7. 所有候选均冷却时等待最早恢复；超过等待上限返回 503。
8. 请求取消、代理停止或应用退出时取消上游请求和等待任务。

## 安全与数据

- 密码只用于登录，不落盘。
- Refresh Token 使用 Windows DPAPI 加密。
- 完整 AIHub Key 默认只驻留内存；必要缓存使用 DPAPI 加密。
- 日志只记录 Key ID、名称、不可逆指纹、状态码、耗时和尝试次数。
- 远程清空 Key 是不可逆操作，必须重新同步、明确列出目标分组、二次确认并输入确认文字。
- 删除过程中限制并发，部分失败不回滚已成功删除项，并提供失败重试。

## 迁移阶段

1. 建立 Wails/Go 应用壳、托盘、单实例、安全存储和构建流水线。
2. 迁移 AIHub 用户功能和固定用户接口客户端。
3. 迁移 Codex/OpenCode 配置读写、备份和回滚。
4. 实现号池同步、分组选择、倍率排序和远程 Key 管理。
5. 实现 Go HTTP/SSE 代理、重试、冷却和统计。
6. 迁移界面、完成端到端测试、生成便携版和安装版。

## 验收标准

- 不安装 Go、Node 或 Python 也能运行发布版。
- Codex 和 OpenCode 可通过本地代理调用 AIHub。
- SSE 不重复、不截断；首字节前失败可按策略切换。
- Key/分组冷却和最低倍率优先行为可通过自动化测试复现。
- 同步失败不会清空最后一次有效号池。
- 远程清空仅影响用户明确选择的分组。
- 应用异常退出后不会留下永久错误的客户端配置。
- 构建产物和日志中没有密码、Token 或完整 Key。
- 代理不会访问任何管理员接口。
