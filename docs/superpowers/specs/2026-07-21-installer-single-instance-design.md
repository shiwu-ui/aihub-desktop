# 安装升级与单实例设计

## 目标

在不改变当前 `1.0.6` 版本号的前提下，让安装版升级时覆盖既有安装目录、保留用户数据，并确保同一时间只有一个 AIHub Desktop 窗口运行。

本次改动记录为下一次版本更新内容，不新增当前版本更新日志条目。

## 方案

### 安装版升级

- 保持稳定的 Electron `appId`：`top.aihub.desktop`。
- NSIS 安装器使用已注册的原安装目录，不提供新的安装目录选择入口。
- 安装新版时由 NSIS 覆盖旧程序文件，不执行旧版静默卸载，不删除 `%APPDATA%` 中的会话、记住账号、配置备份和启动日志。
- 安装前如果旧程序仍在运行，由安装器提示用户先关闭，避免 Windows 文件锁造成不完整升级。
- 便携版仍采用同目录覆盖；它没有安装器和卸载入口。

### 单实例

- 主进程启动前调用 `app.requestSingleInstanceLock()`。
- 未取得锁的第二个进程立即退出，不创建窗口、不初始化托盘、不扫描配置。
- 已取得锁的主进程监听 `second-instance`，收到第二次启动后恢复窗口、取消最小化并聚焦。
- 如果窗口当前隐藏在系统托盘，第二次启动也会显示主窗口。

### 待发布记录

下列内容暂不写入 `1.0.6` 更新日志，下一次版本发布时一并加入：

- 安装版覆盖原安装目录并保留用户数据。
- 便携版同目录覆盖升级。
- Electron 单实例锁和第二次启动唤醒窗口。

## 验收标准

1. 当前 `package.json`、`package-lock.json`、界面版本和现有更新日志仍为 `1.0.6`。
2. NSIS 配置禁止安装时改到新目录，安装器仍保留卸载入口和用户数据。
3. 单实例测试能证明第二个启动不会创建第二个窗口，并能唤醒第一个窗口。
4. 现有登录、客户端配置、供应商大厅、API Key、充值测试继续通过。
5. 构建产物名称仍为 `AIHub-Desktop-1.0.6`，不生成 `1.0.7` 文件。
